# 架构与文件工作台：研究结论

**截止 2026-09-08 03:41:27 UTC，定向评估 28 个项目，覆盖 6 类问题。** 这是一份有证据的广泛扫描，不代表穷尽 GitHub。候选来自公开网页检索、GitHub 仓库搜索、官方关联项目和已知领域基线，没有按 Star 排序。

## 产品判断

首版服务同时维护代码、数据和实验的个人与小团队，让使用者从一个文件连续查到模块职责、内容版本、运行输入与配置、产物和结论。这个组合值得做成可运行工作台，而不只是给架构师 Skill 增加说明。需求强度与首次使用成功率仍是待验证假设。

单独做架构图、文件列表、空间统计、快照差异或实验看板，都已有充分的工具供给。首版重点是连接这些任务，并降低第一次使用成本。文件目录与模块职责保持两个视角；文件位置与完整内容身份保持两个对象；运行记录独立于文件是否改变。这个取舍来自下面的证据，不能被表述为“市场上没有类似产品”。

| 类别 | 定向评估项目 | 本版取舍 |
|---|---|---|
| 架构图与代码地图 | Archify、Archmap、dependency-cruiser、CodeBoarding、CodeCharta、Structurizr Lite、Cocoon Architecture Diagram Generator | 学习可直接体验、稳定模型和来源核验；保留现有架构编辑，独立实现文件视图 |
| 文件组织与性质 | Spacedrive、TagSpaces、organize、Czkawka | 路径/内容/性质分层；不迁移文件，不带入文件动作引擎 |
| 存储观察 | dua、dust、gdu、QDirStat、WinDirStat | 学习比例条、快照、占用口径；完整哈希与实验记录另行建模 |
| 数据版本与实验 | DVC、DataLad、MLflow、Aim、lakeFS | 借鉴独立 Run、输入输出版本；平台导入留待后续 |
| 来源与知识关联 | OpenLineage、Marquez、Renku、Logseq | 采用显式关系与局部导航；不把关联推定为因果或验证 |
| Agent 与软件工作区 | Repomix、Trellis、Backstage | 复用现有模块标识、明确范围、可携带结果；不部署完整工作流平台 |

## 与 Archify 的比较

明确参照是 [tt-a1i/archify](https://github.com/tt-a1i/archify)，而非同名浏览器扩展。核查默认分支为 `2ead014a`，开发版本 2.17.0-dev.1；稳定发布为 [v2.16.0](https://github.com/tt-a1i/archify/releases/tag/v2.16.0)。网页和 main 中的能力不能全部归到稳定发行版。

| 评估维度 | Archify 的一手证据 | 本仓库 v0.3.1 基线 | v0.4.0 的选择 |
|---|---|---|---|
| 第一眼理解 | 官方站直接嵌入真实生成的交互例，图区、场景指南、安装页相连 | README 有退款架构预览，需下载 HTML 后打开 | 提供直接在线试用的合成工作区，先选产物、再查来源 |
| 核心产物 | 类型化 JSON 经确定性编译生成图，支持多种图类型与导出 | 架构模型、HTML/SVG 和可编辑前端组件 | 保留已有编辑；新增实测文件目录、快照与运行记录 |
| 深入阅读 | 源码实现固定 revision 核验；界面有节点搜索、路径与引导故事 | 模块证据、视图、批注和边界检查 | 以明确 snapshot/path 连接文件、来源和旧版本 |
| 分享出口 | 官方文档列出单文件 HTML、SVG、视频、分享图卡等 | HTML、SVG、编辑后模型 JSON | 当前阅读位置可保存为独立 HTML，另有完整元数据 JSON |
| 分发材料 | 可见多 Agent 安装说明、双语站点、公开案例和发布记录 | 双语 README、可下载示例、Release | 给陌生人一个入口与完整任务路径，保留许可说明 |

这些差异涉及产品体验、模型约束和交付形态，无法用“只差营销”解释。Archify 的优势也不意味着本产品应做成另一个架构图生成器。此版选择补足真实工作中的文件追溯，并改善入口与可携带结果。

GitHub API 在本次观察记录了 Archify 53,226 stars、3,483 forks；这只是时点计数。官方站上的赞助链接、案例和安装入口属于可观察分发材料，不构成增长归因。未取得流量来源、转化率、推荐算法或历史榜单证据，无法判断其增长或登顶原因。

**实际试用范围**：在官方站切换工作流/部署示例，打开部署架构产物，暂停故事，启动 Route Probe，搜索并选择 Customers，观察到 11 个可达方向的提示。这证明该次导航和选择行为可用；没有安装 Archify、运行它的编译器或穷尽导出/路径组合。其他候选均为一手文档与指定源码核查，未本机试用。

## 决定首版的五条证据

1. Spacedrive 分开快速抽样摘要与完整校验字段；MLflow 的 pandas 摘要会取样并截短。完整文件身份必须自有清楚口径，不能导入一个 digest 就标为完整性验证。[文件工具研究](file-tools.md)、[数据与来源研究](data-lineage.md)
2. dua 已发布快照及差异，因此“历史快照”是基线功能。首版应连接显式实验来源，不把大小变化自动解释成运行经过。[dua 证据](file-tools.md#dua历史快照已是基线实验来源才是补充价值)
3. DataLad 默认可能不为无变化运行产生新提交。独立 Run 才能保留取消、失败及无产物尝试。[DataLad 证据](data-lineage.md#datalad)
4. 文件标签工具可能通过改名或旁置文件持久化；这会改变实验目录。新工作台将元数据写到被扫描目录之外。[TagSpaces 证据](file-tools.md#tagspaces借鉴多维性质元数据与原目录分开保存)
5. 模块、目录与数据流的产品侧重点不同。Backstage 的所有权模型、OpenLineage 的运行关系和代码分析器的依赖图需要明确映射，不能因为都有“图”就当作同一体验。[架构工具](architecture-tools.md)、[来源研究](data-lineage.md)

## 实现与后续

| 状态 | 范围 |
|---|---|
| v0.4.0 已实现 | 本地只读扫描；内容/位置分离；完整 SHA-256 或未知；历史快照和差异；模块及业务性质映射；复用边界清单；显式输入/配置/输出、指标、结论；三种视图与共同详情；离线 HTML/JSON；合成在线示例 |
| 已保留 | 架构师决策流程、模块范围检查、既有可编辑架构/前端画布 |
| 规划、未集成 | DVC/MLflow/OpenLineage 只读导入、gdu 大规模报告、Repomix 指定范围上下文导出、可审阅的 AI 语义建议 |
| 非目标 | 自动移动/删除、回收空间决策、数据备份、实验调度、后台全盘索引、多用户实时协作、自动科学结论 |

首版选择 **NO_AI**。普通代码可以可靠完成观察、哈希、统计、记录校验与导航；语义建议未来可采用 AI_ASSISTED，但无模型时核心结果仍可得到。AI_CORE 在版本、权限和删除判断上没有必要性。产品经理套件的职责边界已经足够，本版无需修改其仓库。

项目的既有许可决定继续保留：公开可见，但尚未授予开源许可。这是外部采用者必须看到的真实约束；此版没有擅自改变许可，也没有复制研究候选的实现或素材。
